# Infrastructure

Terraform for the GCP project `cs5224-project-508705`. Everything lives in `asia-southeast1` (Singapore),
in a single environment.

## What it creates

| Resource | Details |
|---|---|
| Artifact Registry | Docker repo `apps`, one image per service. Keeps the 3 newest versions of each image; other versions are deleted once older than 7 days. |
| Cloud SQL | `main-postgres`: PostgreSQL 17, `db-f1-micro`, 10 GB HDD, zonal, no backups. Database `configuration_service`, user `app`. |
| Secret Manager | `cloud-sql-db-password`: the `app` user's password (generated by Terraform). |
| Cloud Run | `configuration-service`, `messaging-service`, `processing-service`, `payment-ingester`, `messaging-ingester`. 1 vCPU / 512Mi, scale 0 to 1 (`messaging-service`: 0 to 2), public, unrestricted egress. |

## One-time setup

Terraform keeps its state in a GCS bucket, which has to exist before `terraform init`:

```sh
gcloud services enable serviceusage.googleapis.com cloudresourcemanager.googleapis.com storage.googleapis.com

gcloud storage buckets create gs://cs5224-project-508705-tfstate \
  --location=asia-southeast1 \
  --uniform-bucket-level-access \
  --public-access-prevention

gcloud storage buckets update gs://cs5224-project-508705-tfstate --versioning
```

Terraform authenticates with your Application Default Credentials (`gcloud auth application-default login`).

## Usage

```sh
cd infrastructure
terraform init      # first time only
terraform plan
terraform apply
terraform destroy   # tears everything down (state bucket stays)
```

The first `apply` takes about 10 minutes, mostly waiting for Cloud SQL.

## Deploying images

Services without an image tag run the placeholder `cloudrun/hello` image. To deploy a real image, push it to the
registry, then set its tag in `terraform.tfvars` (copy from `terraform.tfvars.example`) and `terraform apply`:

```sh
gcloud builds submit ../configuration-service \
  --tag asia-southeast1-docker.pkg.dev/cs5224-project-508705/apps/configuration-service:abc1234
```

```hcl
image_tags = {
  "configuration-service" = "abc1234"
}
```

## Useful commands

```sh
terraform output                                                  # service URLs, registry path, SQL connection name
gcloud secrets versions access latest --secret=cloud-sql-db-password  # read the DB password
```

The DB password is also stored in Terraform state, which lives in the private state bucket. Never commit
`*.tfstate` files.
